## 实测结果

移动至独立目录并重新编译探针后，以下命令退出码为 0，完整输出保存在 [android-api35-probe.log](android-api35-probe.log)：

```sh
.venv/bin/python run.py --serial emulator-5554 --package space.nomoloop.blewright.host --probe
```

- 扫描：发现 FFF0 模拟设备，返回原生 ScanResult；错误过滤无结果；stop 后无结果；重复扫描返回预期错误。
- 连接：简单 connectGatt 与带 Handler 的重载均成功，返回实际 BluetoothGatt 类。
- 服务：发现 FFF0 / FFF1 / CCCD；重复 getService/getServices 后对象身份与层级仍一致。
- 写读：旧版 boolean 返回接口和新版 int 返回接口均完成 01020304 写入与一致回读。
- 通知：CCCD 写入成功，通过旧版与新版 onCharacteristicChanged 收到回显；没有同时调用新旧回调制造重复成功。
- 线程：显式 Handler 的连接回调实际运行在指定 HandlerThread。
- 结束：重复 disconnect 仅收到一次断开；连接创建后立即 close 不再回调连接成功。
- 模拟状态单元测试：6 / 6 通过。
- 构建：agent 打包、Java/D8 编译、独立宿主 APK 构建、Python 语法检查通过。

## 本轮发现与修复

1. Hook ready 早于 Application 创建：启动器在运行探针前等待 applicationReady，不再传入空 Context。
2. Hook 返回对象的包装句柄被 Frida 回收：审查所有跨回调保存和返回的对象；缓存对象保留独立引用，getService 返回新的包装句柄。原探针服务发现失败已消失，并补充重复服务查询回归检查。
3. 固定 Java List.add 的 Object 重载，避免对象返回时依赖模糊重载匹配。

## 可重复运行的环境

模拟器和 Frida Server 保留运行；测试宿主已安装。探针启动器会在测试结束时终止自己启动的宿主进程。SDK、APK、虚拟环境等构建产物在忽略目录 dist / .venv / node_modules 内。

## 证据边界

这是 API 35、单模拟外设、前台 GATT Client 的原生接口接管证明，不是任意 Android 版本、所有系统 BLE 接口、涂鸦 SDK 或真实射频通信的兼容性证明。完整通知门控失败组合与忙状态等仍主要由状态单元测试覆盖，不混同为模拟器操作验证。
