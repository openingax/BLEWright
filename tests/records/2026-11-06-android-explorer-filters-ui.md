## 实板发现的接管问题与修复边界

通用硬件主动扫描中，C6 先发带名称的广播，再发空扫描响应。工作站的 name/serviceUUIDs/manufacturerData 已合并保留，但 advertising 是最新原始包（可能为空）；原 Android 转换仅解析 advertising，导致原生 ScanRecord 丢失名称并被新筛选误隐藏。

修复位于 Android 公共投影层 `scan-record.js`：保留当前原始 AD 字段，用服务已提供的合并元数据补齐缺少的原生记录字段。没有 C6、硬件模式或 App 专用分支，不改服务协议或工作站固件；完整原始记录保持字节不变。App 继续读取原生 ScanRecord。

新增验证覆盖：空响应后名称/服务/厂商字段保留、完整 mock/被动记录不变、完整名称优先于短名称、16/32/128 位 UUID、服务数据与 TX power、未知 AD 保留、填充与畸形包。筛选 UI 广播夹具增加末次空扫描响应及合并元数据，防止只测完整 mock 广播遗漏这类问题。


## 最终结果与证据

- 最终 APK 编译、打包、签名校验通过，安装在 LocalGitPhone / API 35 arm64 模拟器。Android agent 重新打包通过。
- 筛选谓词测试覆盖 ASCII/Unicode 空白、阈值边界、Android RSSI 有效范围上界和未知值、组合与默认恢复；通过。
- `npm test` 50/50 通过，其中 6 项为新增的原生广播记录转换回归。
- `verify:explorer` 的 9 组主 UI 流程、`verify:explorer:edges` 的取消/重复/超时场景通过。
- 广播转换修复后再次运行原生接管四组回归、筛选 UI 7 组回归和实板 UI 回归，均通过。
- S3 实测扫描 56 个地址；隐藏无名称后 13 条，再加 RSSI ≥ -70 dBm 后 2 条。关闭两个条件立即恢复 56 条，不重新扫描。
- 只连接 USB 关联查询与广播地址/nonce 双重核实的自有 C6；验证 FFF1 读取、写入回读、通知、取消订阅。恢复测试前值后断开。USB 独立计数增量：reads=6、writes=3、subscriptions=1、notifyRequests=4；其它设备连接数 0。
- 最后保留正式工作站注入会话，已设置「隐藏无名称 + RSSI ≥ -70 dBm」。最后一轮扫描 61 条、显示 3 条，C6 名称正常保留。附近广播随时间变化，因此数量与前轮不同。
- 日志复制后系统剪贴板预览显示本次扫描日志，清空后出现「暂无操作记录」，随后返回扫描页。
- 截图已检查：扫描/筛选弹窗/无匹配/广播详情/设备详情/日志。启动图标资源已打包，APK 声明解析正确。
