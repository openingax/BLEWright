- /dev/cu.usbmodem2021401；USB JTAG/serial 303A:1001；ESP32-S3 QFN56 rev0.2；16MB Flash；8MB PSRAM；MAC 28:84:85:5c:98:8c。

## 调试发现

- IDF 5.5 的 ATT incoming notification 分发表受 BLE_GATTS 条件控制。只编译 GATT Client 会导致读写正常但无通知；开启 GATT_SERVER / ROLE_PERIPHERAL 编译依赖后通知通过。固件仍不广播、不注册业务 GATT 服务。
- 命令跨 USB RX / NimBLE callback 统一通过主机事件队列串行处理，命令事件完成时释放 NPL 包装，避免事件句柄泄漏。
- 租约由周期 FreeRTOS 任务投递主机队列检查，BLE 状态仍只在主机线程修改。
- Mac 外设会先主动断开未使用 GATT 的新连接；租约测试需重连后重新发现并订阅，再进行主机静默。最终观察到本地主动断开 reason=534，而非先前远端主动断开 reason=531。

## 当前状态与缺口

板上运行 BLEWright 固件。原固件恢复步骤已写入 firmware/README.md，完整备份仅存本机。Mac 测试外设为验证临时程序，结束验证后关闭，复测按 README 重新启动。

尚未集成公共 RPC 硬件后端；尚未实测 connect 期间 cancel 的竞争路径、加密/配对、长时间压力、多型号兼容、物理拔插重连；不支持多连接、长读写分片或 OTA。TX 队列满/USB 超时可能丢帧，主机必须监控 droppedFrames 并把超时操作视为未知，不自动重试写入。
