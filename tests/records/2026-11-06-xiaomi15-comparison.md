# Xiaomi 15 原生 BLE 与模拟器接管对比

## 修改前对比矩阵

用户授权在 Xiaomi 15 安装独立 BLEExplorer 并做对比。手机为 Android 16 / API 36，模拟器为 Android 15 / API 35。只复用同一 APK 和同一 UI 测试场景；产品 App 不增加真机/模拟器分支。测试驱动仅启动方式不同（真机直接启动，模拟器经现有工作站注入）。

| 项目 | 两端共同验收 | 状态 |
| --- | --- | --- |
| APK 身份 | 两端安装包 SHA-256 与本地 APK 相同 | 通过；两端与本地 APK 完全相同，SHA-256 见下文 |
| 原生通路 | Xiaomi 不使用 Frida/RPC；模拟器明确使用 esp32 后端 | 通过；真机直接启动且 APK 不含 RPC/Frida；模拟器启动日志明确 esp32 |
| 扫描/筛选 | 名称/RSSI 筛选基于同一批结果，计数变化正确、无额外扫描 | 两端均通过；比较内部筛选规则，不要求射频统计一致 |
| 测试外设身份 | USB 新 requestId 关联查询，广播地址/nonce 一致；只连接自有 C6 | 两端 USB 新身份与广播地址/nonce 匹配；同一 C6，未连接其它设备 |
| 服务及特征值 | FFF0/FFF1/CCCD 可见，FFF1 的读/写/无响应写/通知属性一致 | 两端均发现 3 个服务；FFF0/FFF1/CCCD 和 FFF1 属性一致 |
| 读取/带响应写入/回读 | 相同字节得到相同结果，原生回调成功 | 带响应与无响应写入均回读一致，含大于 0x7F 的字节；所有状态码 0 |
| 通知/取消订阅 | 写入后收到相同通知；取消后写入不再通知 | 两端各收到 2 次通知，取消后写入不再产生通知 |
| 清理 | 恢复初始值并断开；C6 USB 独立计数证明实际无线操作 | 两端均恢复 BLE 初值并断开；独立计数完全一致，临时工具已清理 |

只扫描周围其它设备，不连接或写入；两端顺序测试，避免 C6 单连接冲突。不会以附近设备总数、RSSI 或原始广播字节排列必须相同作为判据。跨系统版本、射频环境和硬件差异单独记录，不能据此宣称所有 BLE 行为完全等价。

首次安装被 Xiaomi 以 INSTALL_FAILED_USER_RESTRICTED 拒绝；用户开启 USB 安装后重试成功。随后通过系统权限弹窗授予本工具“附近设备”权限。未修改其它 App 或手机全局蓝牙配置。


## 最终同包结果

APK SHA-256：`9c4cacf5ea09f2cd02ad766a7430a77897a91100656a9f483adf479899f8bb06`。

| 项目 | Xiaomi 15 原生 BLE（API 36） | 模拟器 → BLEWright → S3（API 35） |
| --- | --- | --- |
| 发现服务数 | 3 | 3 |
| FFF1 属性 | 读取、带响应写入、无响应写入、通知 | 相同 |
| 非法十六进制输入 | 拒绝，未发送 GATT 写入 | 相同 |
| 回调状态码集合 | 0 | 0 |
| App 读取/写入回调 | 5 / 4 | 5 / 4 |
| CCCD 回调/收到通知 | 2 / 2 | 2 / 2 |
| C6 独立读取/写入计数增量 | 7 / 4 | 7 / 4 |
| C6 独立订阅/通知请求计数增量 | 1 / 5 | 1 / 5 |
| 测试初值及恢复值 | 42 4C 45（BLE） | 相同 |
| C6 RSSI | -44 dBm | -29 dBm |
| 总数/有名称/有名称且 ≥ -70 dBm | 42 / 11 / 4 | 55 / 12 / 3 |

写入用例包括 `42 57 30 36` 的带响应写入与通知、退订后的 `42 57 30 37`，以及 `01 23 45 67 89 AB CD EF` 的无响应写入和实际回读。无响应回调本身不当作外设确认，使用回读和独立 C6 计数证明本轮实际收到数据。

## 发现、调整及未完成尝试

- Xiaomi 的 ADB 模拟按键存在字母缺失，例如 `424c45` 进入控件后变成 `42445`；另一轮字母未进入编辑框。App 的校验阻止了提交，不能把这些未完成的自动化尝试计为完整 BLE 回归通过。
- 为两端共用的十六进制输入框增加 ASCII/无联想/英文提示，缩小特征值按钮内边距以避免 Xiaomi 窄屏“取消订阅”换行；没有新增按机型分流的 BLE 实现。
- 对比测试统一改为系统 UI 自动化 ACTION_SET_TEXT，并在点击发送前回读文本；仅操作本 App 可见编辑框，不访问 BLE 或替换回调。厂商输入法对 ADB 按键的兼容性不作为 BLE 逻辑断言。
- 独立 UI 测试 APK 在手机上被拒绝安装，最终使用已有 uiautomator 的测试 JAR；模拟器试装的辅助 APK 已移除，两端临时 JAR 均已删除。旧测试输出器在 API 36 缺少注解类，使用标准简洁输出解决，不修改手机系统。
- 首次从手机轮切换到模拟器轮时，C6 USB 查询出现 Device not configured，发生在 App 启动/连接之前。重新枚举后只重跑模拟器；未重放任何结果未知的写入。

## 验证与证据

最终 APK 重新编译、签名校验并安装两端。最终真机与模拟器 UI 回归均退出码 0，比较脚本逐项断言 APK、测试外设、服务属性、数据、状态、回调数量、恢复值及独立计数一致。Python 语法和 diff 检查通过；真机截图确认按钮标签不再换行。

证据：`dist/tests/explorer/comparison/summary.json`，两端目录中的 `results.json`、`native-callbacks.log`、USB 身份/计数前后快照和界面截图；`cleanup.json` 记录临时工具清理结果。安装保留的是独立 BLEExplorer，未修改 Uwant Android App 或手机全局蓝牙/输入法配置。

结论限于本轮已覆盖的前台 C6 扫描、筛选、服务发现、两种写入、读取、通知与退订流程；未据此宣称完整 Android BLE 等价。后台/进程恢复、配对加密、长写/MTU、厂商特殊服务和其它 Android 版本未在本轮做真机对照。扫描数量和 RSSI 受系统、硬件、位置及扫描时段影响，本轮不对它们作相等断言。
