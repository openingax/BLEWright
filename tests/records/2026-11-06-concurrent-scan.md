# Xiaomi 15 与模拟器同时扫描

用户报告手机能扫描、模拟器扫不到。本轮不连接或读写任何 BLE 设备，也不访问 C6 USB 身份接口。

## 原因与恢复

检查时，工作站 0.4.0 / esp32 / 8876 已就绪，S3 已连接，但没有运行中的 Android 接管启动器。手机已有 52 条扫描结果，模拟器显示蓝牙可用但结果 0。上轮对比测试清理了接管会话，之后直接打开模拟器 App 会使用虚拟蓝牙，不能接收真实 S3 广播。

使用 `npm run explorer:workstation -- --serial emulator-5554` 恢复接管后，未修改 App、固件或工作站配置即可同时扫描成功。验证结束时保留该接管会话运行。

## 实测

两端均使用「隐藏无名称 · 信号不限」。通过并发 ADB 点击启动扫描，主机命令发起时间差小于 1 ms；启动后 1 秒两端均出现新的开始扫描日志，尚未结束或失败。

| 轮次 | Xiaomi 15 原生 BLE | 模拟器 → BLEWright → S3 |
| --- | --- | --- |
| 1 | 47 条（列表显示 9 条） | 58 条（列表显示 13 条） |
| 2 | 52 条 | 60 条 |

两端每轮均约 15 秒自动停止。事件日志中没有连接、读取、写入或订阅请求。第二轮结束的手机 UI 快照没有包含列表顶部，脚本的 UI 断言因此中断；随后根据两端完整 App 日志确认第二轮也正常结束，不把该 UI 断言当作通过。

证据：`dist/tests/explorer/concurrent-scan/results.json` 及两端 `round-1-*.log`；第二轮完成时间来自当时已检查的两端 App 日志，记录在 results.json 中。这里的计数按扫描结果地址去重，名称过滤只影响显示数量。

## 使用条件

手机直接使用本机蓝牙，无需 BLEWright；模拟器需要保持启动器与接管会话运行。单独从模拟器图标重新启动 App 不会自动接入 BLEWright，需重新运行工作站启动入口。电脑睡眠、服务失联或进程结束后也应重新检查连接状态。并发扫描本身不要求 C6 连接。
